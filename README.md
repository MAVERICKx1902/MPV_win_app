# MPV Studio — frameless macOS-style media player UI

A **web-only UI prototype** for a cross-platform media player. Everything you see
runs in the browser today; the codebase is shaped so the whole thing can be
wrapped in **Tauri 2.0** for Windows and Android without touching the React
layer.

```
React 19 · TypeScript · Vite 8 · Tailwind CSS 4 · lucide-react
```

> **What is mocked:** playback uses real HTML5 `<video>` elements, but the
> *pipeline* around them (URL resolution, the Auto-Next engine, the yt-dlp
> downloader) is simulated in TypeScript. In the Tauri build those three modules
> become IPC calls to Rust — the UI never changes.

---

## 1. Quick start

```bash
npm install
npm run dev            # http://localhost:5173
```

| script                | purpose                                                            |
| --------------------- | ------------------------------------------------------------------ |
| `npm run dev`         | Vite dev server (binds `0.0.0.0`, any host — preview/ LAN friendly) |
| `npm run build`       | `tsc -b` + production bundle into `dist/`                          |
| `npm run preview`     | serve the production bundle                                        |
| `npm run lint`        | oxlint (0 errors / 0 warnings today)                               |
| `npm run verify:mocks`| node-side regression check of the mock engine (26 assertions)       |
| **`npm run dev:win`** | `tauri dev` — Windows desktop dev loop                             |
| **`npm run build:win`** | `tauri build` — Windows installer                                |
| **`npm run dev:apk`** | `tauri android dev` — run on an Android device/emulator            |
| **`npm run build:apk`** | `tauri android build` — APK/AAB                                  |

The four cross-platform scripts are wired up and ready; the Rust crate they need
is generated by `npx tauri init` (see [`src-tauri/README.md`](src-tauri/README.md)
for the mapping table and the platform prerequisites).

## 2. What is in the box

### Window shell — “macOS on the web”

- Frosted **glass** outer window (`backdrop-blur` + translucent layers + hairline
  borders) with 22 px rounded corners on desktop, edge-to-edge on phones.
- Custom **traffic lights** (close / minimise / zoom) that reveal their glyphs on
  hover. Close → an “app closed” screen with a reopen card; minimise → the window
  animates out and leaves a restore control. Zoom → **cinema mode**.
- Draggable title bar (`-webkit-app-region: drag`, ready for
  `data-tauri-drag-region`), centred now-playing breadcrumb, resolving spinner,
  auto-next toggle, downloader badge, inspector-menu.
- Status bar with mpv-flavoured core info (`mpv-core 0.39.0 · hwdec=auto-safe`),
  live “auto-next in Ns” chip and a stats toggle.

### Player

- `<video>` with **perfectly rounded bezels** inside the window, real chrome-free
  media, poster frames and buffering spinner.
- Custom control bar: scrub slider with buffered range + drag preview, ±10 s,
  previous/next, volume (hover-expanding), speed popover (0.5×–2×), subtitles,
  shuffle, repeat / repeat-one, stats, queue, fullscreen.
- Cinema mode, mpv-style **stats overlay** (`--osd-level=3` cosplay), mocked
  subtitle line, auto-hiding chrome, keyboard map:

  | key | action | key | action |
  | --- | ------ | --- | ------ |
  | `Space` / `K` | play-pause | `N` | next (resolve + play) |
  | `←` / `→` | ±10 s | `P` | previous |
  | `↑` / `↓` | volume | `F` | cinema mode |
  | `M` | mute | `S` | stats overlay |
  | `C` | subtitles | `Y` | Auto-Next on/off |
  | `D` | downloader | `Q` / `I` | queue / info inspector |
  | `⌘K` | command palette | `?` | shortcut reminder |

### Auto-Play Next (simulated URL resolution)

1. While the last **5 s** play, an **Up-Next card** slides in with a countdown
   ring, the target artwork, the reason (“Next episode” / “Next video from this
   channel”) and *Play now / Cancel / keep watching* actions.
2. On the `<video>` **`onEnded`** event the resolver runs a 4-step simulated
   `yt-dlp -J` trace (`extracting → probing formats → format selected → hand-off`)
   in a modal, then swaps the source and keeps playing.
3. Sequencing rules live in `findAutoNext()`: next episode of the same series →
   next item of the same kind → wrap around the library (honouring repeat mode).
4. The **URL bar** and **⌘K palette** feed the same pipeline: paste a
   YouTube/Twitch/Vimeo/HLS/MP4/magnet URL and it resolves deterministically
   (FNV-1a seeded) into a playable queue entry — *Open* plays it now,
   *Queue* appends it.

### Downloader (dummy `yt-dlp` module)

- Sleek **slide-out panel** (right drawer on desktop, bottom sheet on mobile):
  URL field with validation + clipboard paste + one-tap samples, **Video (MP4) /
  Audio (MP3)** cards, quality/bitrate selectors, subtitle / cover-art / playlist
  switches, live **command preview** and the `-o` output template.
- **Progress simulation**: a pure reducer (`advanceDownload`) drives the bar,
  percentage, throughput, ETA and elapsed clock, while a **terminal** streams a
  faithful `yt-dlp` transcript — `[debug]` config, extractor lines, 5 % steps with
  real `MiB/s ETA`, then `[Merger]`, `[ffmpeg]`, `[ThumbnailConvert]`,
  `[Metadata]`, `[MoveFiles]` and `exit code 0` *after* 100 %.
- Jobs can be cancelled, retried, replayed in the player, and the app raises a
  macOS-style “Download complete → saved to …” banner.

### Library, queue & inspector

- Horizontally scrolling **library shelf** (desktop) and grid (mobile) with
  artwork gradients, duration and source badges.
- Queue with current-item equaliser animation, inline reorder/remove, up-next
  spotlight and total runtime.
- Inspector tabs: **Queue**, **DLs** (job cards + terminal) and **Info**
  (metadata, source URL, and the Web → Tauri mapping table).
- ⌘K **command palette** (play any library item, run any action).

### Responsive / Android-ready

- ≥ 1024 px: window chrome + right inspector.
- 640–1024 px: window chrome, inspector collapses.
- < 640 px: full-bleed edge-to-edge with a thumb-reachable bottom tab bar
  (**Player / Library / Queue / Grab**), safe-area padding and a bottom-sheet
  downloader — i.e. the layout the APK will ship.

## 3. Project structure

```
src/
├── App.tsx                    # shell composition, hotkeys, overlay orchestration
├── types.ts                   # shared domain types (IPC-ready shapes)
├── index.css                  # Tailwind v4 theme tokens, glass/scroll utilities
├── components/
│   ├── shell/                 # TitleBar, TrafficLights, StatusBar, UrlBar,
│   │                          # InspectorSidebar, CommandPalette, MobileNav
│   ├── player/                # VideoStage (overlays, up-next card), ControlBar
│   ├── downloader/            # DownloaderPanel, DownloadForm, JobCard, Terminal
│   ├── library/               # LibraryRail + LibraryGrid
│   ├── queue/                 # QueueList
│   └── ui/                    # IconButton/Tip, Toggle, Segmented/Badge, Slider
├── hooks/
│   ├── usePlayer.ts           # transport + Auto-Next resolution engine
│   ├── useMediaLibrary.ts     # queue, current item, simulated openUrl()
│   ├── useDownloader.ts       # ticking driver for the mock jobs
│   ├── useHotkeys.ts          # global keyboard map
│   └── useToasts.ts           # notification queue
└── lib/
    ├── urlResolver.ts         # URL → metadata, provider table, sequencing
    ├── downloader.ts          # pure yt-dlp/ffmpeg job state machine
    ├── mockData.ts            # library, quality ladder, source badges
    └── utils.ts               # cn(), time/byte formatting, URL validation
```

### Mock → native seams

Everything that will become IPC is isolated:

| module                | seam                                                                  |
| --------------------- | --------------------------------------------------------------------- |
| `lib/urlResolver.ts`  | `resolveMediaUrl()` → `invoke('resolve_url', { url })`                 |
| `lib/downloader.ts`   | `createDownloadJob()` / `advanceDownload()` → `invoke('start_download')` + `listen('download://progress')` |
| `hooks/usePlayer.ts`  | the `<video>` element → native mpv surface; `onEnded` → `end-file` IPC event |
| `components/shell/TrafficLights.tsx` | window buttons → `getCurrentWindow()` API                 |

## 4. Placeholder media

Real, tiny MP4s (12 s, ~180 KB, H.264/AAC + poster JPEGs) are committed under
`public/media/` so the demo is offline-safe and the Auto-Next loop is
observable. Regenerate or restyle them with:

```bash
FFMPEG=/path/to/ffmpeg ./scripts/generate-placeholder-media.sh
```

The script (see `scripts/generate-placeholder-media.sh`) renders the
“THE MIDNIGHT SIGNAL / EPISODE 0x” slates with ffmpeg’s `drawtext`, gradient
boxes, noise, vignette and a synthetic ambient audio bed.

## 5. Verification

```bash
npm run verify:mocks   # 26 assertions over the resolver + downloader state machine
npm run lint           # oxlint — clean
npm run build          # tsc -b + vite build
```

`verify:mocks` exercises the pure engine in node: provider detection (YouTube
sub-domains, Twitch, HLS, magnet…), deterministic resolution, Auto-Next
sequencing and wrapping, monotonic download progress, the post-100 %
post-processing stream and log ordering.
